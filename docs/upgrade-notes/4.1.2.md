No configuration, account or identity-store changes are required for the deployment availability fix (#94).
Keep the installation record, settings, certificates and keys when upgrading.

Deploys now keep a safely stopped controller with a classified drive or limit fault (including an unpowered
drive), and the deploy script and installer warn with its name. Inspect the cause and settings, particularly a
fault first seen after upgrading; restore the plant and explicitly `ClearFault` before commanding motion. No
automatic fault clearing occurs. `/health` and `/health/ready` remain unhealthy for plant latches; Docker now uses
`/health/available` for software and I/O availability. Older images without that endpoint still use strict
readiness, including on rollback, so a plant fault can still fail their verification.
