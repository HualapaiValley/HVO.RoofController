Upgrade an installer-managed controller or emulated rig while idle with `sudo hvo-roof-install upgrade`.
Upgrade the separately installed per-user CLI or Mac app as that user, without sudo. Keep the installation record,
identity store, settings, certificates and device keys; do not reinstall or replace them to upgrade.

Native Linux authentication remains opt-in. Existing native enrollment, subject IDs, credential hashes and access
revocations are preserved. Enabling native authentication migrates the identity store to
schema 2. Once migrated, rollback to 4.0.x is refused because it cannot read that schema; keep a complete pre-upgrade
backup or VM snapshot and repair forward with a compatible release. Never restore an old credential file on its own.

Kiosk PIN sign-in now permits roof operation only, including for administrators. Use password or native sign-in in
the CLI, terminal interface or web UI for administration. Existing password and PIN hashes remain valid; newly set
virtual passwords require at least seven characters and new personal PINs require four digits. No default credential
or automatic Linux-user enrollment is added.

Managed splash files are upgraded while retaining removal backups. Existing display choices are preserved; supported
explicit video modes use the corrected Plymouth-to-kiosk handoff. Verify the complete screen, actual resolution and
boot/shutdown artwork after reboot. Ubuntu rigs remain unrotated and use the HAT emulator.
