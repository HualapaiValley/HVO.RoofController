Upgrade a controller or emulated rig running 4.2.0 while the roof is idle, with `sudo hvo-roof-install upgrade`.
Upgrade separately installed per-user CLI and Mac clients as their user, without sudo. Keep the pre-upgrade backup
or VM snapshot and the installer's previous-version assets for rollback. No identity-store schema change: the new
display names, short names, last sign-ins and command history are optional data a rollback to 4.2.0 still reads.

**Open now asks for a safety override.** The safety interlock's default, `RoofSafety:InterlockMode`, is now `Warn`.
No real safety source exists yet, so the conditions read Unknown, and every Open needs the override: the web UI, the
kiosk, the Mac app and `hvo-roof ui` ask for it (**Open anyway**), and it is audit-logged. Scripts that open the roof
must add `hvo-roof open --override-safety` (or `overrideSafety=true` on the API). To keep Open as it was in 4.2.0, set
`RoofSafety:InterlockMode` to `Off`. Close and Stop are never gated.
